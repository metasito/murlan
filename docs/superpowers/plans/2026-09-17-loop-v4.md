# Loop v4 — Resilience and Efficiency Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** A loop that always knows where a ticket stands, including CI, keeps that knowledge across restarts, fixes a red CI run cheaply and only once, and stops paying for context and models it does not need.

**Architecture:**
- The loop stays a state machine derived from git, the tracker and the ledger, and the supervisor still spawns one process per phase.
- v4 adds CI as a fourth input to `derive()`, including a settle phase that needs no session.
- Every counter that lives in `main()`'s memory today is rebuilt from the ledger and the tracker.
- The worktree stays until merge or park, so a fix round resumes the build in place.
- A failure shared across branches is owned by one ticket instead of being investigated by every branch it hits.

**Tech Stack:**
- Node 24 `.mjs` supervisor, `.ts` tests under `tools/loop/tests/`, run with `npm run loop:test` (`node --test`).
- `gh` CLI.
- Claude Code `-p --output-format stream-json`, and Claude Code hooks (`.claude/settings.json`).

**Spec:** `docs/research/2026-09-17-loop-audit.md`. It is written in Task 0, holds the audit figures below, and every "what this buys" in this plan cites it.

## Context

This is the 4th loop rewrite. It follows an audit of the 22 tickets run since the Sep 14 rework (`d5854ea7`, one process per phase).

**What the Sep 14 rework achieved:**
- $26.56 → **$14.86** per landed ticket.
- Tickets that never landed: 36% → **16%**.
- Phase D's share of spend: 74% → 28%.

**What is still wrong:**

| # | Defect | Evidence |
|---|---|---|
| D1 | `derive()` knows nothing about CI (`loop-derive.mjs:306`) | After the 07:14 restart, #1082 resumed at E on a head whose CI run was already red. It re-pushed nothing and posted a false "all boxes closed" comment. |
| D2 | `main()` keeps its counters in memory (`queue-loop.mjs:1915-1926`) | A restart reset the CI-round cap: the screen said "fix round 2/3" on the 3rd red run, and the no-commit park could not fire. `handoffs` and `nextPhase` survive a retry, so healthy #1079 reached 7 of `MAX_HANDOFFS`=8. A retry session's cost is never added to `spent`. Four of `main()`'s parks write no ledger row. |
| D3 | Phase F removes the worktree before CI answers | Every red run costs a new phase-A process, a full review round and a new E+F process: $2.5–4 per fix round, $15.80 on #1077. The board labels the resumed row "claim" although no claim runs. |
| D4 | Nothing records what a fix round ruled out, or notices a failure shared with other branches | #1077's second fix session redid the first one's investigation. The accountRecovery 401 hit both #1077 and #1082. |
| D5 | Phase C has no bound | #1077's build: 449 turns, 360k context, $24.63, 12 identical full `tsc` runs. Its E process then found `agent:check` red and bounced back for 153 turns. |

**Totals for the current loop:**
- Fix rounds are 13% of spend.
- 27% of tickets pushed a branch that went red in CI.
- Phase C is 55% of spend.

**Owner decisions:**
- **Shared CI failure:** fix the root cause once, through one shared ticket.
- **Who builds this:** a dedicated session, not the loop.
- **Reviewer tier:** keep sonnet reviewers and amend rule 29.

## Global Constraints

- **The ledger can be rebuilt from these three sources.** No new state file. Durable facts live in git, the tracker (issue comments) or `.loop-logs/tickets.jsonl`, which is already kept and never pruned.
- **Do not reduce `MAX_REVIEW_ROUNDS` (4), and do not remove review from fix rounds.** A fix round's review is resized (T9), not skipped. Every new head still needs a sha-bound `REVIEW` plus `VERDICT`.
- **No self-defeating safeguards** (CLAUDE.md). Every gate needs a floor, and a ceiling stated in code, not prose.
- **Comment budget:** at most 6 added comment lines (3 in a test) *and* no more comment than code, counted over the whole branch.
- **Test style:**
  - `tools/loop/tests/*.test.ts` under `node --test`.
  - Inject `gh` and `git` as seams, following `settleReplay.test.ts`, `claim.test.ts` and `queueLoopMain.test.ts`'s fake `io`.
  - `derive()` is faked through `LOOP_GH_SCRIPT`. It must now dispatch on its argv (`issue view`, `pr view`, `run list`, `run view`, `ls-remote`).
- **Run only what you touched:** `node --test tools/loop/tests/<file>.test.ts`, plus `npx tsc --noEmit` and `npx eslint tools/loop`. `loop:test`, jest and Playwright run in CI (rule 2).
- **The loop is stopped while this is built.** Never edit inside a live `.worktrees/agent-*`.
- **`tests/rulesAreSingleSourced.test.ts`:** every new `.md` in `.claude/commands/` or `docs/agents/` names `docs/agents/RULES.md` and restates no rule.
- **Keep protocol comments short.** New tracker comments (`CI-RED`, `FIX-NOTES`) are ≤15 structured lines, because the picker prints every comment into every fresh process.

### Task 8: A failure shared with other branches is owned once

**What this buys:** D4 and the owner's decision "fix the root cause once". No second branch spends a round rediscovering a known failure.

**Files:**
- Create: `tools/loop/sharedRed.ts`
- Modify: `tools/loop/ciVerdict.ts` (`recentRedRuns`), `tools/loop/queue-loop.mjs` (hand-back), `.claude/commands/queue.md` (C-fix)
- Test: `tools/loop/tests/sharedRed.test.ts` (new)

**Interfaces:**
- `recentRedRuns(repo, gh, sinceMs): {runId, branch, headSha, url, testIds}[]`.
  - Reads `gh run list --workflow ci.yml --limit 40` for failed runs within 48h.
  - Reads `--log-failed` once per run id, cached under `.loop-logs/red-<runId>.ids` (a new ephemeral artefact).
- `decideShared(mine: {branch, testIds}, others, issues): {kind: "none"} | {kind: "file", testId, evidence} | {kind: "known", issue, testId}`.
  - Shared means the same test id failed on `main` or on another branch.
  - Issues are listed with label `shared-red`, deduped by the test id in the title. A closed issue whose test id fails again is `reopen`.
- `checkShared({repo, gh, mine})` never throws, like `mainHealth.checkMain`.
- Protocol for the fix round when `shared` is set:
  - "file": the branch fixes the root cause in this diff and puts `Closes #<shared>` in its PR body.
  - "known" with the owning fix already on `main`: the supervisor runs `gh pr update-branch` and settles again. No session is spawned.
