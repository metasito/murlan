## Replit Builder Requirements — Murlan

> **Context:** Murlan is an Expo React Native app using `react-native-reanimated`, `useWindowDimensions`, `useSafeAreaInsets`, and the base menu components (`MenuLayout.tsx`, `MenuCard.tsx`, `MenuButton.tsx`). All changes below must respect the constraints in `replit.md`: **Exchange Phase logic must not change**, **Flying Card Animation must not change**, and **Friends System Architecture must not be broken**.

***

## REQ-1 — Exchange Announcement Redesign

**Goal:** Make the exchange announcement informative and visually engaging by showing usernames and animating the card transfer.

### REQ-1.1 — Show Username, Not Avatar

- In the exchange announcement overlay/banner, replace any avatar image or icon with the player's **plain text username** (e.g. `rotonmeta`).
- Style the username using the **Rajdhani** font, gold color `#C9A84C`, and a font size consistent with other in-game headings.
- Both the giver and the receiver usernames must be displayed.

### REQ-1.2 — Descriptive Text Label

- Display a human-readable text line in the format:
  **`[Username A] dà [card name] a [Username B]`**
  (e.g. `rotonmeta dà 3 di Picche a marco99`)
- If the exchange is mutual (two-way), show both directions stacked:
  ```
  rotonmeta dà 3 di Picche a marco99
  marco99 dà Asso di Cuori a rotonmeta
  ```
- Card name must use full Italian notation: rank + suit (e.g. `3 di Picche`, `Asso di Cuori`, `Jolly`).
- Text must be readable: use Inter font, white or light color, minimum font size 14.

### REQ-1.3 — Card Movement Animation

- Using **`react-native-reanimated`** (already in the project), animate a card graphic moving from player A's side of the screen to player B's side, representing each exchange.
- If mutual: animate both cards simultaneously or sequentially (your choice, but both must be shown).
- The animation must use `withTiming` or `withSpring` for the positional translation.
- **Do NOT modify the existing flying card animation used during gameplay (`pileState`)** — this is a separate overlay component scoped to the exchange phase announcement only.
- The card graphic shown in the animation should match the actual card being exchanged (same rank and suit).
- Duration: ~600–800ms per card movement. After animation completes, the overlay auto-dismisses.

***

## REQ-2 — "Stanza" Room Menu Layout Fixes

**Goal:** The room lobby screen (`Stanza`) must be fully usable in **both portrait and landscape** without any element going off-screen or requiring unwanted scrolling.

> Reference screenshots attached (IMG_8195 = portrait, IMG_8196 = landscape/tablet).

### REQ-2.1 — Fix "In attesa di giocatori…" Button Clipping in Landscape

- The `In attesa di giocatori...` disabled button currently overflows or is cut off in landscape mode.
- It must always be **fully visible** and within safe area bounds in both orientations.
- Use `useSafeAreaInsets()` to calculate bottom padding/margin.
- The button must remain at the bottom of the content, but within the viewport — not floating outside.
- Use `useWindowDimensions()` to detect landscape (`width > height`) and apply a compact layout variant if needed.

### REQ-2.2 — Player List Fully Visible in Landscape (No Vertical Scroll)

- The **Giocatori (x/4)** section shows up to 4 player slots. All 4 must be visible simultaneously in landscape **without scrolling**.
- To achieve this: **reduce the vertical padding and height of each player row** (e.g. reduce from ~56px to ~36–40px), while **keeping the font size unchanged**.
- Reduce internal row padding (top/bottom) to reclaim vertical space.
- The player avatar circle/initial badge and username text must remain clearly legible at reduced row height.
- The "Host" label below the username may use a slightly smaller font if needed (minimum 11px).
- Do NOT remove any player slot or hide any information.

### REQ-2.3 — "Invita Amici" Section with Scroll Indicator

- The **Invita Amici** friend list must show **at least 3 friends** without requiring a scroll.
- If the user has more than 3 friends, the list must be **scrollable** and this must be visually communicated:
  - Show a **subtle gradient fade** at the bottom of the friend list (e.g. a `LinearGradient` from transparent to `#031008`) to hint at more content below.
  - Alternatively or additionally, show a small downward chevron icon (`˅`) at the bottom of the list area.
- Each friend row should be compact (similar to REQ-2.2 height constraints) but readable.
- The "Nessun amico online" empty state must still display correctly when the list is empty.

### REQ-2.4 — Full Layout Adaptation for Portrait and Landscape

- In **portrait**: use a **single-column vertical scroll** layout — Room Code → Mode → Giocatori list → Invita Amici → Action Button, stacked top to bottom.
- In **landscape**: use a **two-column layout**:
  - **Left column:** Room Code card, game mode selector, Invita Amici section.
  - **Right column:** Giocatori (x/4) player list.
  - Action button (`In attesa di giocatori...` / `Lascia Stanza`) spans full width at the bottom or is placed below the right column.
- Use `useWindowDimensions()` to switch between these two layout modes reactively.
- All elements must respect `useSafeAreaInsets()` on all sides (especially notch and home indicator areas).
- The overall screen must use the existing `MenuLayout.tsx` base component if possible, and respect the dark felt color scheme (`#031008`, `#0B3B25`, `#C9A84C`).

***

## REQ-3 — Rename "Play with friends" → "Gioca con amici"

- Find every occurrence of the string `"Play with friends"` in the codebase (in UI labels, button text, screen titles, or navigation labels).
- Replace all occurrences with `"Gioca con amici"`.
- This is a text-only change; do not alter any navigation logic, routing, or functionality.
- If the string appears in a translation/i18n file, update it there. If it's hardcoded, update each hardcoded instance.
